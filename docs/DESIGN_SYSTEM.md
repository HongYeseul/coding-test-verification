# 디자인 시스템

바탕은 종이, 글자는 잉크입니다. 도장은 종이에 찍는 것이라 화면을 장부처럼 다룹니다. 중성색은 아주 약하게 따뜻한 쪽으로 두고 채도를 낮춰, 브랜드 파랑이 그 위에서 잉크로 읽히게 합니다.

브랜드는 파랑입니다. 예전에는 초록 하나가 브랜드 정체성이면서 동시에 ‘승인·성공’이라는 의미색이었습니다. 도장판이 초록으로 차오를 때 그게 우리 색이라서인지 다들 잘해서인지 구분되지 않았습니다. 브랜드를 파랑으로 옮기면서 두 축을 갈랐고, 승인은 색이 아니라 도장이 찍혔다는 사실이 지게 했습니다. 별도의 ‘성공 초록’이 사라져 색이 하나 줄었습니다.

스펙 시트는 [`design/`](design/)에 네 장 있습니다 — 도장, 색, 타이포, 구성 요소.
값을 바꿨으면 `python3 docs/design/build-sheets.py`로 다시 만듭니다. 시트에 적힌
값은 `src/app/globals.css`의 토큰과 같아서 한쪽만 고치면 어긋납니다.

## 색

`src/app/globals.css`의 `:root` 한 블록에 모여 있습니다. `light-dark()`라 테마 전환에 재정의가 필요 없습니다.

| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| `--canvas` | `#f5f3ee` | `#15171a` | 바탕(종이) |
| `--surface` | `#fdfcfa` | `#1c1f24` | 종이 위에 올라앉는 면 — 카드, 목록 묶음, 다이얼로그, 입력 |
| `--ink` | `#1a1d22` | `#ebe9e3` | 본문 |
| `--sub` | `#6d6a63` | `#9a978f` | 보조 문구 |
| `--line` | `#e3dfd5` | `#2f3238` | 경계선 |
| `--soft` | `#eeebe3` | `#23262c` | 눌린 면, 호버 |
| `--brand` | `#1d5091` | `#8fc0f2` | 도장, 오늘 열, 포커스 링 |
| `--brand-soft` | `#e6edf7` | `#1b2e47` | 브랜드 배경면 |
| `--primary` | `#1a4784` | `#9ac6f5` | 채운 버튼 |
| `--primary-hover` | `#143866` | `#b2d5f8` | 채운 버튼 호버 |
| `--primary-ink` | `#ffffff` | `#0f2038` | 채운 버튼 글자 |
| `--warn` | `#8d5a15` | `#e5bc78` | 검수 대기 |
| `--danger` | `#ab3a31` | `#efa19a` | 반려, 파괴적 동작 |

`--brand`는 바탕 위에 얹는 색(글자·도장·선)이고 `--primary`는 채우는 면(버튼 배경)입니다. 대비 기준이 다르므로 값도 다릅니다. `--canvas`는 페이지 바탕에만 쓰고, 그 위에 올라가는 것은 모두 `--surface`입니다. 두 값의 차이가 작아 그림자 없이도 면이 구분됩니다.

면은 세 층뿐입니다. `--canvas`가 페이지 바탕, `--surface`가 그 위에 올라앉는 것(카드·목록 묶음·다이얼로그·입력), `--soft`가 눌리거나 마우스가 올라간 자리입니다. 층을 더 만들지 않습니다.

그림자는 **떠 있는 것에만** 씁니다. 토스트와 팝오버가 전부입니다. 카드와 목록은 1px 테두리와 `--surface`의 밝기 차이로 구분되므로 그림자를 얹으면 종이 위에 종이가 뜬 것처럼 보입니다.

## 도장

도형은 `src/components/seal.tsx` 한 벌입니다. `SealDefs`가 필터·마스크·심볼을 루트 레이아웃에 한 번만 심고, 화면 곳곳의 `<Seal>`은 `<use>`로 참조만 합니다. 정의를 담은 SVG는 `display: none`이 아니라 `width=0 height=0`인데, 숨기면 일부 브라우저에서 참조 대상이 그려지지 않기 때문입니다.

```tsx
<Seal className="size-[30px] sm:size-[38px]" tilt="-3deg" />
```

잉크색은 `currentColor`라 감싼 요소의 `color`가 정합니다. `.seal { color: var(--brand) }` 한 줄로 라이트·다크가 모두 맞고, 채운 머리말 위에서는 흰 도장이 됩니다.

글자 대신 엄지를 새깁니다. 도장에 글자를 새기는 건 누가 찍었는지 밝히려는 것인데, 모든 멤버가 같은 도장을 쓰므로 밝힐 게 없습니다. 판독성도 이유입니다 — 문자는 획 사이 간격만큼의 해상도를 요구하지만 픽토그램은 실루엣만 있으면 되므로 16px에서도 방향이 읽힙니다.

크기에 따라 두 가지를 씁니다. 40px 아래에서 잉크 얼룩은 질감이 아니라 색이 바랜 것처럼 보이므로, 작은 크기용은 얼룩을 빼고 테두리 흔들림만 남깁니다. 웹앱은 전부 38px 이하라 작은 크기용만 씁니다. 큰 크기용은 확장 프로그램의 `extension/seal.js`에 있습니다.

기울기는 `--seal-tilt`로 넘깁니다. 누르는 동안에도 각도가 고정이어야 하기 때문입니다 — 손목이 정한 각도는 찍는 중에 변하지 않고, 회전을 같이 움직이면 ‘찍혔다’가 아니라 ‘돌면서 등장했다’로 읽힙니다.

## 상태

상태는 형태로 먼저 구분하고 색은 거들기만 합니다. 색을 구분하지 못해도, 흑백으로 인쇄해도 읽힙니다.

| 상태 | 형태 | 색 |
|---|---|---|
| 승인 | 잉크로 채운 도장 | `--brand` |
| 검수 대기 | 같은 엄지를 점선 윤곽으로만 그린 도장 (`<Seal ghost />`) | `--warn` |
| 반려 | 둥근 네모 테두리 + `×` | `--danger` |

검수 대기가 점선 도장인 이유는 ‘내가 찍었지만 동료가 확인해야 잉크가 채워진다’는 서비스의 약속이 형태로 보이게 하려는 것입니다. 채움과 점선은 실루엣이 달라 색 없이도 갈립니다.

이 세 형태는 네 자리에서 똑같이 씁니다 — 도장판 칸, 기록 목록의 상태 글자 앞, 상세 모달, 최근 활동의 줄 앞. 같은 상태가 화면마다 다른 모양이면 사용자는 둘을 다른 것으로 읽습니다.

### 응원

응원은 하트 하나입니다. 윤곽은 아직 안 누른 상태, 채움은 누른 상태이고 색은 `--danger`입니다. 도형은 `src/components/cheer-button.tsx`의 `HeartIcon` 한 벌입니다.

하트를 상태 표시로 쓰지 않습니다. 응원은 검수가 아니고 집계에도 들어가지 않아, 도장·점선 도장·`×`와 같은 줄에 놓이면 안 됩니다. 목록에서는 상태 칸과 떨어진 오른쪽에 수만 답니다.

### 기록값

기록 종류를 쓰는 그룹에서는 도장 아래에 값이 붙습니다. 고정폭 11px(넓은 화면 12px)에 `--sub`이고, 목표가 있으면 차이를 옆에 답니다. 목표를 못 지킨 값만 `--warn`이 되고 지킨 값은 색이 바뀌지 않습니다 — 잘한 것에 색을 칠하면 도장이 지고 있던 ‘찍혔다’는 신호가 흐려집니다.

아직 끝나지 않은 값은 `13:00~`처럼 물결로 열어 둡니다. 결과가 아니므로 목표와 견주지 않습니다. 칸 높이는 기록 종류를 쓰면 58px에서 76px로 늘어나고, 그 값은 `rowHeight()` 한 곳에서만 정합니다.

### 차트

차트는 둘입니다. 시각을 기록하는 그룹의 ‘내 리듬’은 선, 시간을 기록하는 그룹의 ‘내 착석 시간’은 막대입니다. 둘 다 인라인 SVG이고 토큰만 씁니다 — 잉크는 `--brand`, 못 지킨 값은 `--warn`, 축과 눈금은 `--line`, 글자는 `--sub`, 속을 비운 표시의 안쪽은 `--surface`입니다. 목표는 점선 가로선 하나이고, 목표를 못 지킨 점과 막대만 `--warn`입니다. 아직 진행 중인 날은 채우지 않고 테두리만 그립니다.

차트에는 `aria-hidden`을 주고 **바로 아래에 같은 내용을 글자 한 줄로 둡니다.** 그림을 못 보는 사람이 같은 것을 알 수 있어야 하고, 그 한 줄은 대부분의 사람에게도 그림보다 빨리 읽힙니다. 내 기록이 하나도 없으면 차트를 아예 그리지 않습니다.

## 타이포

글꼴은 세 벌이고 `src/app/layout.tsx`가 `next/font`로 심습니다. 빌드 때 받아 같은 도메인에서 내려주므로 방문자 브라우저는 Google에 요청하지 않고, 한글 글꼴은 유니코드 범위별로 잘려 있어 화면에 쓰인 조각만 받습니다.

| 역할 | 글꼴 | 쓰임 |
|---|---|---|
| 명조 | Noto Serif KR 600·700 | `h1`, `h2`, 현황판의 큰 숫자 — 장부의 활자 |
| 고딕 | IBM Plex Sans KR 400–700 | 본문, `h3`, 버튼, 입력 |
| 고정폭 | IBM Plex Mono 400·500 | 날짜·시각, GitHub 아이디, 초대코드 |

| | 크기 | 굵기 | 자간 |
|---|---|---|---|
| `h1` | 34px · 명조 | 700 | `-0.03em` |
| `h2` | 22px · 명조 | 600 | `-0.024em` |
| `h3` | 17px | 600 | `-0.012em` |
| 본문 | 15px | 400 | 행간 1.6 |

한글은 글자 폭이 고르기 때문에 큰 제목에서 자간을 안 붙이면 성기게 벌어집니다. `px`가 아니라 `em`이라 크기를 바꿔도 비율이 유지됩니다.

다이얼로그·팝오버 제목은 `h2`이고, 그 안의 절이 `h3`입니다. 요소로 크기를 고르지 않습니다.

## 조작 요소

버튼은 네 가지입니다.

| | 높이 | 모서리 | 쓰임 |
|---|---|---|---|
| `.btn` | 40px | 8px | 기본 |
| `.btn-primary` | 40px | 8px | 화면에서 가장 중요한 하나 |
| `.btn-ghost` | 글자 높이 | — | 닫기처럼 테두리가 방해되는 자리 |
| 도장 버튼 | 48px | 10px | 도장 찍기 창의 제출 버튼 |

도장 버튼만 크고 모서리도 한 단계 둥급니다. 이 서비스에서 사람이 누르려고 오는 버튼이 그것 하나이기 때문입니다. 채운 면 위라 도장은 흰색이 됩니다. 손가락으로 쓰는 기기에서는 모든 버튼이 44px로 커집니다.

이름 칩은 높이 36px에 `rounded-full`이고, 왼쪽에 상태 표시가 들어갑니다. 오늘 띠에서 씁니다.

`globals.css`의 기본 입력 규칙은 **글자를 받는 입력에만** 겁니다. 체크박스·라디오·파일은 스스로 모양을 가지고 있어 반드시 빼야 합니다. 빼지 않으면 너비 100%와 테두리가 씌워져 라디오가 막대처럼 늘어납니다. 실제로 그렇게 한 번 깨졌습니다.

처음 한 번 정하는 설정은 셀렉트가 아니라 라디오 목록으로 놓습니다. 셀렉트는 가장 긴 항목만큼 넓어지고, 펼치기 전에는 설명을 하나밖에 못 읽습니다. 견줘 보고 고르는 자리에는 맞지 않습니다.

## 모서리

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--r-control` | 8px | 홀로 서는 조작 요소 — 버튼, 입력, 셀렉트, 도장판 칸 |
| `--r-surface` | 12px | 다른 것을 담는 면 — 카드, 목록 묶음, 다이얼로그 |
| — | `rounded-full` | 도장 |

Tailwind에 `rounded-control`·`rounded-surface`로 노출합니다. 테두리가 있는 면의 안쪽 모서리는 `calc(var(--r-surface) - 1px)`로 테두리 두께만큼 줄입니다.

## 확장 프로그램의 제약

확장은 번들러가 없어 웹앱 컴포넌트를 가져다 쓸 수 없고, 콘텐츠 스크립트에는 페이지의 CSS 변수가 닿지 않습니다. 그래서 도장 도형은 `extension/seal.js`에, 색 토큰은 `extension/popup.css`와 `extension/content/overlay.css`에 한 벌씩 더 있습니다. 팔레트나 도형을 바꿀 때 같이 봐야 합니다.

확장 아이콘은 웹앱 파비콘에서 굽습니다. 자세한 내용은 [`extension/README.md`](../extension/README.md#아이콘-다시-굽기)에 있습니다.
